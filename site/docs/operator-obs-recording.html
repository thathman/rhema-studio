OPERATOR GUIDE

OBS, recording & streaming

OBS owns its own online Preview, Program, stream, and legacy recording controls. These stay independent from congregation screens.

OBS integration in repositoryNative recorder code in repository · acceptance pending

OBS is its own production path

The OBS role is for the OBS director. Rhema can connect to OBS on another computer and expose separate online Preview and Program controls, scene selection, transition information, and stream status reported by OBS. An OBS Take affects the OBS program; it must not silently switch a congregation display or Stage receiver.

OBS stream and OBS recording

Stream and recording statuses shown by the OBS integration describe what OBS reports. They are not proof of a Rhema-native recording, a saved archive, or a successful camera view on every audience output. Keep OBS's own scene composition and credentials under OBS/host control.

Rhema-native recording

The repository contains a separate host-owned recorder service for one selected congregation output's final composited Live picture plus an approved audio input. The output ID remains pinned for the session. Private Preview, Stage, Comms, OBS, and other congregation outputs must not leak into the file. The native preflight is macOS-first.

  • The recorder service and host commands are present, but the current frontend does not show a complete Live recording dock.
  • Do not describe OBS recording as Rhema-native recording.
  • Audio/video sync, disk-fault behavior, sustained resource load, crash recovery, and device output fidelity still need acceptance before a release claim.
  • Stream and recording acceptance require real OBS and output checks; screenshot state is not enough.

See Recording and the owner-approved recording contract for source selection and safety rules.

The documentation's OBS UI images contain simulated stream/recording numbers, so they are not used as public status evidence here.
