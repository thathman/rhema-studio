APPROVED DIRECTION · NOT IMPLEMENTED

Recording

The planned Rhema recorder is for a congregation service output. It is separate from OBS's online stream recording.

Rhema-native recording is not implemented in the current main application. The repository's OBS integration can report or control OBS's own recording state; that is not Rhema's service recorder.

Approved native recording source

The owner-approved first version records one explicitly selected named congregation output. It captures that output's final composited Live picture—camera, Scripture, lyrics, graphics, transitions, or intentional blank—plus approved church mixer audio. The selected output ID stays pinned for the session.

What must stay out

  • Private Preview and unfinished drafts.
  • Stage or backstage cues and private Comms.
  • OBS-only scenes and other congregation outputs.
  • Anything outside the selected congregation output and approved audio path.

Safety and performance work still required

  • Host-owned start, stop, and permission checks.
  • Clear recording state and service markers in Live and History.
  • Disk-space guards, recoverable files, and crash recovery.
  • Measured CPU, GPU, memory, disk, encoder, and receiver load with real video.
  • Real-device checks confirming the recorded frame matches the selected output.

Until those pieces are built and accepted, don't promise a Rhema-native recording feature or use an OBS recording screenshot as evidence. Read the Rhema Native Service Recording contract for the full approved behavior.

For the existing OBS boundary, see OBS & streaming responsibilities.
