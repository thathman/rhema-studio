CODE IN REPOSITORY · ACCEPTANCE PENDING

Recording

Rhema's native recorder code is in the repository. It is separate from OBS's online stream recording.

Status: the repository contains a host-owned Rust recording service and Tauri commands that record one selected congregation output with an approved audio input. The preflight currently supports macOS first. A complete user-facing Live recording dock, sustained service validation, and real-device performance and recovery acceptance are still outstanding; this is not a claim of release-ready recording.

Approved native recording source

The owner-approved first version records one explicitly selected named congregation output. It captures that output's final composited Live picture—camera, Scripture, lyrics, graphics, transitions, or intentional blank—plus approved church mixer audio. The selected output ID stays pinned for the session.

What must stay out

  • Private Preview and unfinished drafts.
  • Stage or backstage cues and private Comms.
  • OBS-only scenes and other congregation outputs.
  • Anything outside the selected congregation output and approved audio path.

What exists and what remains

  • Host commands start, stop, mark, preflight, and report the native recording service; a separate host grant is required for paired-device control.
  • The recorder code pins a selected congregation output and uses its host-side rendered frames. Stage, private Preview, other congregation outputs, and OBS remain separate.
  • Local recording files, manifests, disk checks, and interrupted-session recovery logic are present in the Rust crate.
  • The current native path is macOS-first. A completed Live recording dock and user-facing recording archive workflow are not shown in the current frontend.
  • Audio/video sync, crash and disk-fault behavior, sustained resource load, offline operation, and actual output fidelity still need acceptance on supported hardware.

Until the remaining UI and acceptance work is complete, describe the recorder as implemented in part; not release- or device-accepted. Do not use an OBS recording screenshot as evidence of Rhema-native recording. Read the recorder contract and approved recording direction for current source details.

For the existing OBS boundary, see OBS & streaming responsibilities.
