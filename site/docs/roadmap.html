STATUS REFERENCE

Roadmap / in development

This page separates repository implementation from approved design direction and work that still needs integration or acceptance.

How to read this page: “Code in repository” means implementation surfaces are present in the current source tree. It is not a release, full-workflow, security, offline, or hardware acceptance claim. “Approved direction” means product behavior has been specified; it does not mean the feature is built.

Product surfaces with code in the repository

  • Desktop Prepare, event structure, content selection, design library, Live console, Preview/Program model, and output management.
  • Service data, role-scoped actions, LAN pairing and host service endpoints.
  • English and Yoruba content data and output-specific language rendering paths.
  • OBS integration, Comms and Stage service paths, plus Google TV Receiver, Rhema Cam, OBS Companion, local MCP, and Engage code areas.

These surfaces have differing levels of completeness. A single code path or browser-shim view does not establish that every combined user journey works.

Approved direction with implementation or acceptance still open

  • Unified production UX: finish coherent Prepare navigation, editing/reordering, save/reopen, and safe multi-output Preview-to-Take journeys.
  • Operator family: complete browser operator experiences, permissions, reconnects, and real desk acceptance for each role.
  • Design editor: complete the native Avnac/Saraswati design editor. Avnac source is GPL-3.0; licensing review must resolve before importing it into the public repository.
  • Recording: implement and measure the Rhema-native selected congregation-output recorder, crash recovery, and performance safeguards.
  • Timing and Comms: finish the complete Timekeeper and Stage workflows and validate private voice/cues on real devices.
  • Connected devices: accept Google TV, Rhema Cam, and OBS Companion workflows on named supported hardware.
  • Collaboration: build church collaboration and synchronization with explicit conflict and offline behavior.
  • Engage: complete the approved hosted and phone/TV congregation journeys; deployment is not claimed.
  • Quality: complete bilingual end-to-end review, accessibility, recovery, WAN-off, and service-load acceptance at appropriate milestones.

Product safety boundaries

  • Plan, Preview, Program, and History remain distinct.
  • Saving or editing must not silently change a public output.
  • Only explicit Take changes the selected audience output.
  • Stage and Comms remain private; OBS and congregation productions remain independent.
  • Design proposals and screenshots from the browser shim are not proof of native or hardware behavior.

This summary follows the feature-coverage inventory and relevant approved contracts. Status can change as code and acceptance evidence are integrated; this page intentionally avoids delivery dates.
