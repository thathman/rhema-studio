CONNECTED PRODUCTION

Connected operators & LAN browser access

Rhema's host can pair other desks on a local network. The full browser-based role application is still being built.

Host API and pairing in repositoryComplete browser operator app in development

What runs in the browser today

The repository contains host endpoints for pairing, role-checked commands, live-state reads, camera feeds, and selected remote pages. Joining a host and role-scoped backend actions are present in the code. This is not the same as a complete, responsive browser workspace for every role.

The project also has a development browser shim for the frontend. Unless explicitly configured for a test backend, that shim uses simulated state; a page that renders in the shim is not proof that a browser is connected to a real Rhema host.

Local network access model

  1. The main computer runs the service host and enables pairing.
  2. The host issues a pairing code and assigns a named role and scope to the joining desk.
  3. The host service checks each command against that role, current service, output scope, revision, and grant.
  4. The host can pause or revoke a paired desk; a browser cannot grant itself additional authority.

Network boundaries

  • Use the church's trusted local network and the host address shown by Rhema.
  • Use the authenticated pairing flow; never publish pairing tokens, QR codes, certificate details, or private host addresses.
  • Do not forward the host API to the public internet or disable authorization to make a demo work.
  • Some pages require HTTPS for browser capabilities such as microphone access.

Availability: browser role pages, secure reconnect, least-privilege flows, and real tablet/phone acceptance are still in development. Do not advertise a no-install operator application as complete.
