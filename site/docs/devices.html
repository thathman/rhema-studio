DEVICES & INTEGRATIONS

Devices & companion apps

Several companion and connected-tool projects have code in the repository. That does not establish release readiness or acceptance on physical hardware.

Related code in repositoryReal-device acceptance pending

Google TV Receiver

The Android Receiver project provides a target for receiving and rendering Rhema output. Installation, reconnection, display compatibility, and sustained service operation need device-specific validation before support claims can be made.

Rhema Cam

The mobile camera project is intended to connect a phone camera to the production workflow. Camera permissions, network stability, thermal behavior, latency, and output quality must be checked on supported phones and networks. Do not assume a screenshot from the development shim demonstrates a working camera link.

OBS Companion and OBS Director

The separate desktop Companion connects to a different computer's OBS, adds camera feeds, and reports camera tally. Rhema Studio's OBS Director controls OBS scenes and recording, and reports OBS stream status through the configured integration. Neither is Rhema's approved native service-output recorder; see OBS & streaming responsibilities and Recording.

MCP workflows

The opt-in local Rhema --mcp stdio service-draft flow is implemented: it can read selected service and library data and create revision-checked drafts that a person can open and review in Prepare. MCP cannot approve a draft, Take a scene, or change a public output. Native editable design authoring and MCP-driven Live actions are not claimed.

Rhema Engage

Quiz code exists in the application and the engage-cloud worker. The worker contains browser join, display, and QR routes. It has not been deployed as a hosted service, and phone/TV end-to-end acceptance remains pending. Do not describe Engage as available to congregations today.

Collaboration and synchronization

Church collaboration and home-based synchronization are approved product direction. A complete hosted collaboration service, account model, conflict resolution, and offline synchronization acceptance are still in development. Rhema's local-first workflow should remain usable without making a cloud account the control plane for a local service.

Support wording: use “code exists; hardware acceptance pending” unless a specific device, app version, and test result support a stronger claim. No specific model, resolution, frame rate, or network range is promised by this page.

See LAN browser access, Camera operator, and the connected devices QA contract.
