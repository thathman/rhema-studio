SERVICE HISTORY

History & run review

Review a saved run checkpoint without restoring its plan or changing a live output.

Read-only timing review in current mainPhysical output acceptance pending

To open a run review, go to History → What went live → Service log → Recent service runs, then choose Review for a saved run.

Plan compared with actual timing

When a saved service run has a readable checkpoint, History shows planned event durations beside elapsed time derived from the run journal. A difference appears only when both the estimate and a complete actual duration are available. A journaled event missing from the captured plan is labeled Not in captured plan and has no planned estimate; this label does not say when or why it was added.

When a duration is not final or not known

  • For an active event, the elapsed time ends at the last saved checkpoint. The row says at last checkpoint, and its difference is marked Not final.
  • An event with no journal start mark is shown as Not started, not as zero minutes.
  • If the run was interrupted, recovered across a missing interval, lacks a valid timing anchor, or has no finish mark, the affected duration remains unknown.
  • Only complete, supported timing intervals receive a final difference. Missing evidence is not inferred.

What the review does not prove

The journal timing summary does not prove that an audience screen rendered or acknowledged a particular event. Check output status and acknowledgements separately. Reading a checkpoint is a review action: it does not restore the captured rundown into Prepare, take a scene, or send content to Program.

Screenshot status: the repository's public captures predate this History review and do not show the current screen. This page uses no conceptual image as a substitute. Native persistence and physical output behavior require their own acceptance evidence.

Implementation evidence

  • History timing review builds the event rows and presents their evidence state.
  • Saved run checkpoint parser includes supported event timing metadata.
  • Focused review tests cover complete, active, unstarted, interrupted, recovered, and unplanned events.
