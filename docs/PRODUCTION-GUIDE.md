# Rhema Studio — production operator guide

For the person running outputs, OBS and the stage screen. The volunteer guide (`docs/QUICK-START.md`) covers the Standard view; this page covers everything behind it. Services are built in Prepare only; Present's **Advanced** view (the original dashboard: transcript, detections and its own queue) is for listening checks and recovery, over the same service.

## Outputs (Production → Screens → Open outputs, or Settings → Outputs)

- Each output is a window on a monitor or an NDI sender, with its own theme and a role:
  - **Congregation**: the themed frame (verses, lyrics, slides, pictures, quick screens).
  - **Stage**: plain high-contrast text — the live words in every language, NEXT, the operator's note, key and tempo for a song, the timer, and any message you send.
  - **Signage**: library pictures on a loop (so many seconds each) for a foyer screen, optionally only on set days and times (local clock; outside the window the theme background shows). Nothing in the service changes it: going live, Clear, rehearsal and theme edits leave it alone.
- **Looks:** each output has a main look (Look, in its settings) and, under **Advanced: content-specific looks**, optionally a different look for Bible, Songs, Hymns, Slides or Pictures on that output. Design → **Used on…** lists which outputs use each look, with **Open output** to change it; Design itself only designs the looks.
- Removing one output never touches another. Home lists every output as on/off and warns when only the stage is on.
- Home's readiness also checks the plan (#213 preflight): "Planned to end at 12:40", a warning when an item is planned past its **end by** ("Sermon is planned to end at 10:55, 5 min after its end by 10:50"), a note when the main service has no start time, and a note for a scene whose camera layer has no stream address.
- A theme's **logo** draws in a corner; it is hidden on transparent (OBS) themes unless you tick "Show on transparent".

## OBS and NDI

- **OBS connection (optional):** Settings → Remote control → "Connect to OBS" with OBS's address, port (4455) and WebSocket password (OBS → Tools → WebSocket Server Settings). The Present header then shows OBS's own recording state and time ("OBS ● REC 00:12:31" or "not recording"; never guessed). From its menu: start or stop recording (each asks twice), and mark "Sermon start", "Sermon end" or anything else: the mark goes into the service log with the recording time, and into the recording as a chapter on OBS 30.2+ recording to Hybrid MP4. If OBS is closed, Rhema retries every 15 seconds; nothing else depends on it.

- Use a transparent theme (for example the Lower Thirds builtin) on an NDI output for keying. Pictures and quick screens key like verses; background pictures fill the frame, so use them only on the congregation output.
- **Browser Feed** (a kind of output, ARCH-002): a web page on the church network instead of a window or NDI sender. Start the HTTP listener on the network (Settings → Remote control), add an output of kind Browser Feed, copy its link from the output's settings and paste it into OBS (Browser source, 1920×1080), or scan its QR code there with a TV, tablet or phone on the church Wi-Fi to open it in that browser; turn the output on. It shows exactly what the output would: its looks, scene, sources, lower third and ticker; transparent where the look is keyed. Anyone with the link can watch it on the network: **New link** closes the old one. Videos do not play in a browser feed. While it is on, its card in Outputs says how it is doing: "1 page · showing the latest", "No page is showing it", or in red "behind: not showing the latest" when a page has not drawn the newest frame for 3 seconds (a stuck TV browser, a slow network).
- **Google TV / Android TV (Rhema Receiver, #198)**: a TV with no browser (a Chromecast with Google TV) shows a browser feed full screen with the Rhema Receiver app. Install it once from a computer (`android-tv/build.sh`, then `adb install -r android-tv/build/rhema-receiver.apk` with the TV's developer options and wireless debugging on). Open Rhema Receiver on the TV: it shows its name, address and a six-digit code. In Rhema, open the browser feed's settings → **Show on a Google TV**: Rhema looks for TVs on the network by itself and lists them by name and address (**Find TVs** looks again), so you do not type an address. Pick the TV whose address matches the one on its screen (Rhema never picks for you, because another device could pretend to be a TV), type the code from the TV's screen, **Show on TV**. Before it sends the feed's link, Rhema checks with the TV that it really shows that code; the code itself never goes over the network, and a device only pretending to be a TV gets nothing. If no TV is listed (some church Wi-Fi blocks this kind of search), type the address the TV shows instead. The code is always needed, and each check counts as one of the TV's five tries. Rhema Receiver older than 1.2 cannot do the check: Rhema asks you to update it. The TV shows the feed and keeps it: after a restart or a power cut it opens the same feed again, and if Rhema or the network is gone for a while it keeps the last picture and picks up again by itself. OK on the remote shows the address and a new code (to send another feed); five wrong codes lock it until OK is pressed, so only someone who can see the TV can change what it shows. If the feed gets a **New link**, the TV says so: send the feed again.
- **What this output follows** (ADR 0001): "Everything put on air" (the default) shows the latest thing shown, as the projector does. "Only these" makes a feed that follows chosen sources: Bible, Songs, Hymns, Slides, Pictures and the **Ticker**. Each source keeps its own live value, so a Bible feed for OBS keeps the verse while a hymn is on the projector and changes the moment the next verse is shown; no one has to pick destinations. Give it a lower-third look as its main look, or a different look for the Bible only under **Advanced: content-specific looks** in the same settings. A feed that follows only the Ticker shows the ticker and nothing from the service (the ready-made **Rhema Ticker | Alpha** is one, on a transparent look); following the Ticker also ticks "Show the news ticker". Black and Logo cover every feed, the ticker feed too.
- **Present → Live → Sources** lists every live source and who changed it last and when ("Romans 8:28 · by Tolu 10:42": the operator name from Settings, a joined desk or phone, or "Auto"):
  - **Bible, Songs, Hymns, Slides, Pictures** (when an output follows chosen sources): what the feeds hold and how many feeds; take it off (×) and **Restore** it.
  - **Ticker** (once it has run): running, held still or off, with its first words. × takes it off every screen (as Stop in Present → Ticker); **Restore** brings back the same words, starting the crawl again.
  - **Timer** (once it has started): running or paused, with the time left (or so far). Pause and resume it here.
  - **Each camera** from Production → Cameras: sending, not sending or the camera router off, and how many scenes use it. **Hide from scenes** makes every scene with that camera show its fallback words (or its background) there, without changing any scene; **Restore** plays it again. Use it when a phone camera points the wrong way or someone walks in front of it.
  - Every change goes into the service log with who made it. In rehearsal the buttons wait: rehearsal never touches the real ticker, timer or cameras. Joined desks and the phone page see the same list; a phone (or desk) with the Present role can take the ticker off, pause the timer or hide a camera too.
- **Activate on Bible feeds**: once an output (or a scene on one) follows Bible, a verse in Present → Quick find (**Bible feeds**) or in Detections (**Activate on Bible feeds**) can go to the Bible feeds alone: OBS lower thirds and Bible browser feeds change, the projector and other main screens keep what they show, and the verse waits in the preview for Take live.
- **A stage display can follow chosen sources too**: Outputs → edit a stage output → What this output follows. A pulpit monitor following the Bible keeps the verse while a hymn is on the projector; the band's stage following everything shows the hymn.
- NDI frames come from the output window's canvas. A stage output sends NDI too (the stage view is drawn on the canvas, #191), so an NDI viewer on the platform can be the stage display.
- Health: Home → outputs line (for an NDI output it also says how many receivers are connected, so "nobody receiving yet" means OBS has not picked the source up), Present header "n/m outputs on". If NDI frames stop reaching the network, a warning names the output, readiness shows "not sending", and the app restarts the sender once a minute at most; after that turn the output off and on yourself.

## Remote control (Settings → Remote)

OSC addresses and HTTP commands do exactly what the buttons do, with the same safety rules (nothing goes on air before it has loaded):

| Action | OSC | HTTP `{"command": …}` |
|---|---|---|
| Next / Previous item or slide | `/rhema/next`, `/rhema/prev` | `next`, `prev` |
| Show the preview live | `/rhema/send_to_live` | `send_to_live` |
| Continue the reading | `/rhema/verse_next`, `/rhema/verse_prev` | `verse_next`, `verse_prev` |
| Step the Bible panel (preview only) | `/rhema/bible_next`, `/rhema/bible_prev` | `bible_next`, `bible_prev` |
| Output on / off | `/rhema/show`, `/rhema/hide`, `/rhema/on_air <bool>` | `show`, `hide`, `on_air` |
| Run a macro | `/rhema/macro "service-start"` | `macro` with `"value": "service-start"` |
| Theme, opacity, confidence | `/rhema/theme <name>`, `/rhema/opacity <0–1>`, `/rhema/confidence <0–1>` | `theme`, `opacity`, `confidence` |

`confidence` sets how sure speech recognition must be before Auto puts a heard verse on air (default 0.8); below it the verse waits in the preview.

Macro ids: `service-start`, `offering`, `prayer`, `service-end`, plus your own: Present → Cues → New cue… builds one from the same actions (Next, Clear, quick screens, timer, stage message, rehearsal off) in the order you choose; it is saved on this computer and its id (from its name, e.g. `baptism`) is shown under it for a Stream Deck or OSC controller. Present → Cues shows each macro's steps.

**Phone remote:** start the HTTP API with "Accept commands from other devices on this network" ticked, press "Pair a device", and scan the QR code with a phone on the same Wi-Fi. It opens a page with big Next, Previous, Back on air and Clear buttons and what is on air (or that rehearsal is on, or that the computer is waiting for an approval answer); press Pair once. If the Wi-Fi drops an answer the phone tries again by itself and the computer never does one press twice; "No answer…" means check the screen before pressing again. Without the camera, open the address shown under the code and type the six digits. The phone stays paired until it is revoked. What the phone shows (on air, rehearsal, waiting for approval) follows the computer within a second, also when the Rhema window is minimised or behind another app.
The phone also lists each **live source** (Bible, Hymns, Songs…, the Ticker, the Timer and each camera) with what it shows and **Take off** / **Put back** (**Pause** / **Resume** for the timer, **Hide** / **Show** for a camera), and the **production notices** for its role: answer Seen / Ready / Unable, or type a message to the main desk. What the phone may do follows its role in Settings → Remote (a Bible phone takes off only the Bible source). Talking from a phone needs a secure page (see Talk).

**Production → Screens** is the show's routing view: a card for every output with its kind (display, window, NDI, browser feed) and who it is for, where it goes (the monitor, the NDI source name OBS sees, the network), which sources it follows, how it presents them (full screen or a scene, lower thirds, ticker, keyed over a transparent look), its language, its look with a small preview (and how many content-specific looks it has), what it is showing now (a scene, a reference, Black, Logo) and its signal (NDI receivers, browser feed pages). **Edit output** opens its settings; nothing on this page takes anything live. **Add a ready-made feed** adds a named output for OBS: "Rhema Bible | Full", "Rhema Bible | Lower third" (keyed, with name bands), "Rhema Lyrics | Full", "Rhema Lyrics | Lower third" or "Rhema Ticker | Alpha" (only the ticker, on transparency), sent over NDI or as a browser feed. Each is a new output that starts off (turn it on in Outputs when you need it); the name is also its NDI source name, so if an output already has it you are told and nothing is added. No existing output changes. Above it, **Needs attention** lists, most serious first, a failing NDI sender, a browser page that is not showing the latest, and outputs on air that nobody receives. It shows only what Rhema can actually measure.

**The service log** (Archive → Earlier logs, or Keep log) records what went on the screens, each live source turned on, off or back ("· Hymns"), each scene taken or released (SCENE), the run-of-show events, and every command from a paired device with its name ("next · by Femi's laptop"). Production notices and the talk channel are never in it.

**If Rhema closes unexpectedly** (a crash, a forced quit, a power cut) during a service, the next start shows a banner with what was on the screens then. **Put back on the screens** brings back the program, each live source, the outputs that were on with their scenes, the run-of-show event, and the service timer (still counting the minutes Rhema was closed, if it was running); **Not now** leaves everything off. Nothing goes back on air by itself. The **service log** comes back by itself (it is history, not the screens): what went up and when, each item's actual time, so the planned-versus-actual report and Keep log still cover the whole service, with a line saying where Rhema closed. Quitting from the Dock or at logout also counts as unexpected (the offer is harmless: choose Not now). Rehearsal is never put back.

**Who can send these:** anyone on the network while a listener runs, unless you set a key or pair devices in Settings → Remote. Pairing: start the HTTP API, press "Pair a device", and on the phone or controller send the six-digit code once to `/api/v1/pair`; it receives its own token (HTTP header `X-Rhema-Key`, or first OSC argument) and can be revoked on its own later. Start a listener just before the service and stop it after (a listener left running starts again, the same way, the next time Rhema starts, unless it accepted other devices with no key or paired device: that one waits for you, with a message); if the controller software runs on this laptop, untick "Accept commands from other devices on this network" so only this computer is accepted. Details: `docs/rhema-studio/13-remote-control-threat-notes.md`.

## Sound (walk-in music, backing tracks)

**Backing track for a song.** In the song editor, add the track (MP3, M4A, WAV, OGG) under "Chord charts, sheets and backing tracks". In Present, while that song is on air or is the item you are on, the Sound button lists "Backing track for <song>" above the other sounds. It plays only when you press Play; screens are not changed.

Import MP3, M4A, WAV or OGG files in Prepare → Media (they are listed under Sounds). In Present, the ♪ button in the header lists them: Play, Pause/Resume, Fade out (3 seconds), Stop, Repeat and Volume. One sound plays at a time, on this computer's sound output; no screen changes, and NDI carries no sound. Each Play is a line in the service log. Rehearsal mode does not silence the ♪ button: Play there is always a deliberate press.

A sound can also be a service item (Prepare → Media → Sounds → Add): when Next reaches it, the sound starts and every screen keeps what it shows; Next then carries on to the item after it. It plays only when reached going forward: Previous steps over sound items, and Next at the end of the service does not replay a last sound. The rundown shows "playing" next to it. In rehearsal a sound item does not play (Present says so).

## Lower thirds

Present → Lower third: a name and an optional title, shown as a band near the bottom of the outputs where "Show lower thirds" is on (Outputs → edit; usually the NDI stream with a transparent theme). It stays up through Next, Clear and new items until you press Hide. The projector shows it only if you turn it on for the projector; stage and signage screens never show it.

## Videos

Prepare → Pictures → "Import pictures or videos…" takes MP4, MOV, M4V and WebM (MP4 with H.264 plays everywhere). A video item plays on every congregation output, streamed from the media folder; **sound comes from the main output only**, so two screens never echo. Per item: Loop (otherwise it holds the last frame) and Sound. NDI carries the picture, not the sound; an NDI-only output in a hidden window may send fewer frames per second on some systems (check before relying on it). Very large videos make the "service as a file" export large, because the file travels inside it.

## QR links on screen

Prepare → Slides → "QR link": type a full `https://…` address (giving, sign-up, the bulletin). The code is drawn in the app, offline, on a white panel with the address printed beside it, so people see where it goes; nothing is tracked. Only plain http(s) links are accepted. The preview shows the words; the code appears on the outputs.

## Scenes for the congregation (Production → Programs)

- A scene places live content, colours, Library pictures and camera places on one frame. Each live layer follows chosen sources (Bible, Songs, Hymns, Slides, Pictures) or whatever is on air, in a look from Design (or the output's own looks). **Hold what it shows now** keeps a layer on one verse while the rest follows; **Follow live again** releases it.
- A **Camera** layer plays a camera on the church network: give it the camera's stream address (WHEP), e.g. from MediaMTX `http://<its computer>:8889/<camera>/whep`. Each screen, NDI output and browser feed plays it directly (no sound: the room hears the room), filling the layer's box; until it connects, the scene's background shows there (or the words you give it under **While the camera is not playing, show**, e.g. "Camera back shortly", in the look's text style), and a dropped camera reconnects by itself. Only addresses on the church network are used. Put a Bible or lyrics layer over it for "camera with the words".
- A **Clock** layer shows the service timer (Present → the timer: set the minutes, Start) in a look's text style, filling its box: a countdown to the start of service on the projector, or the time so far. It stops at 0:00 on the screens. Each screen counts by itself, so nothing is resent every second; it keeps counting with the screen covered or locked.
- A Clock can instead show **the time of day**, or **a countdown to a time** you choose (the service start, say 10:00): today's, or tomorrow's once today's is long gone; it stays at 0:00 when the time comes. Put both side by side on a "Before service" scene.
- A **Ticker** layer shows the running ticker (Present → Ticker) as a band filling its box (along the bottom when added); a **Lower third** layer shows the lower third that is up, laid out in its box; both show nothing while nothing runs. A scene with its own ticker or lower third **owns** it: while that scene is up on an output, the ticker (or lower third) shows only in the scene's box, never also across the whole screen, even with the layer hidden, and whether or not the output's own ticker or lower-third switch is on. On a browser feed (a Google TV, a TV browser, OBS) a Ticker layer that nothing sits over crawls on its own strip, so the rest of the picture stays still and a camera beside it stays smooth; for the smoothest TV, keep logos and pictures beside the ticker's box rather than over it.
- A **Logo** layer shows the church logo from Design → Brand Kit, whole and fitted in its box (top-right when added). A new logo there reaches the scenes on air.
- **New from** offers ready-made scenes: Full screen, Bible and lyrics, Lyrics on a picture, Camera with the Bible, **Full camera**, **Camera in a corner** (what is on air, with a small camera top right), **Sermon split** (the preacher's camera left, the verse right) and **Welcome** (the logo, a countdown to the service: choose its time, and the ticker). **Save as preset** keeps the scene's arrangement (not any held verse) as your own preset under **Your presets**, beside the ready-made ones; the pencil renames it, the bin deletes it. A preset of the same name is replaced.
- Arrange: drag a layer to move it, drag its corner to resize, arrow keys to nudge (Shift for 5%). Box, crop and opacity can be typed. Layers draw bottom first; reorder them in the list.
- **Take** puts the scene on the chosen congregation output (it saves first). Next to the scene's background, **Take** chooses how it comes on: **Cut** (as before) or a cross-fade of 0.3, 0.5 or 1 second; releasing it fades the same way. Black and Logo always cut. **Back to its own feed** returns the output to full frame; **Restore** takes the scene again. Taking a scene changes no other output (OBS feeds stay as they are), and a new verse never changes which scene is up. Black and Logo cover every screen and feed, scenes included.
- **From Present:** the **Scenes** strip under Live (Standard view) takes saved scenes without leaving the live console. It shows what each congregation screen is arranged as now; with more than one, choose the screen first. Click a scene (its small picture shows that screen's look of it), then **Take scene**; **Own feed** goes back to the screen's own feed; **Restore** takes its last scene again. Take scene only rearranges that screen: what is live stays live, and OBS feeds and other screens do not change. In rehearsal the strip works for practice: a Take there shows in Rhema (marked *In rehearsal*, never *On air*) but no screen changes, and every screen has its own scene again when rehearsal ends. The arrow beside **Scenes** folds the strip away. Scenes are made and edited here in Programs, not in Present.
- Edits stay in the composer until Save or Take.

## Cameras (Production → Cameras)

Phones on the church Wi-Fi can be cameras: **Add a camera** (Pulpit, Choir…), scan its QR code with the phone, allow the camera and press **Start camera**. Each camera goes once to the camera router that comes with Rhema; scenes and TVs take it with **Use in a scene…** (or its WHEP address in a Camera layer), and OBS with its RTSP address in a Media Source. Phones need the secure phone page (Settings → Remote control → "Secure page for phones (https)"). Nothing goes to the internet. Step by step, ports and security: [rhema-studio/cameras.md](rhema-studio/cameras.md).

## Show health (Production → Show health)

What each audience is actually getting, from real signals only:

- **Needs attention** (top): the serious problems first: an NDI sender failing, a TV or browser page stuck behind, and a **scene on air whose camera is not sending** ("Pulpit camera is not sending; "Sermon split" on Main shows its fallback words there"). Production → Screens shows the same list.
- **Sunday preflight:** the same checks as Home's readiness.
- **Cameras:** every camera you added, and every camera layer in a scene, with what Rhema's camera router says: **Sending (H264) · watched by 2 screens or programs**, **Not sending**, or **Camera router not running**; and which scenes and screens use it. A camera address that is not Rhema's router says Rhema cannot see whether it sends. **Open Cameras** goes to Production → Cameras.
- **Browser feeds and Google TVs:** each browser feed says **2 screens showing the latest**, **Behind** (a page is stuck: reload it) or **No screen watching**. Each Google TV you sent the feed to with **Show on a Google TV** is listed under it. **Check TV** asks the TV which feed it is showing ("Showing this feed", "Showing another feed", or what its screen says is wrong); it needs Rhema Receiver 1.1 on the TV. **Forget** only removes the TV from this list.
- Home's readiness warns when a camera in a scene set on a screen is not sending (**Open Cameras**), and notes a browser feed that is on with no screen watching.
- Rhema asks the camera router every 5 seconds and each feed every 2 seconds, and only while Home, Present or Production is open.

## Operators: host and join (Production → Operators)

- **Host:** the computer that runs the service keeps every control. Start the HTTP listener on the network (Settings → Remote control), then **Pair a device** and give the code to the operator. Set each paired device's role there: **Timekeeper** moves only the event clock; **Bible** activates a typed reference and steps it (the main screens take it only when no song, hymn or slide is up there; the Bible feeds always do); **Screens** takes scenes to congregation outputs; **Present** does all of these and moves through the service; **Present and settings** adds settings.
- **Join:** on the other computer, Production → Operators → Join a host: the host's address and port (shown in Settings → Remote control on the host), the code and a name. The joined desk shows what is on the host's screens, the live sources, the run of show with **Now**, and the expected end; a Timekeeper starts the next event, goes back one or starts any event, moves the service's **running late** by 5 minutes either way, and runs the **service timer** (it shows the host's timer counting; Start / Pause, −1 / +1 min). It can also **Hold** the service with a reason ("Waiting for the pastor") and **Resume** it, exactly like the main desk's Hold; the host's log names the desk, and every desk shows the hold with who made it. Nothing there changes a screen.
- **When a desk may be out of date:** the host sends its state every couple of seconds. If a joined desk hears nothing for more than 5 seconds, or is reconnecting, it says **Last update N s ago**, and its clock and timer are dimmed and marked **may be out of date** until the host is heard from again (the host's service is not affected). If the joined computer's clock and the host's differ by more than 2 seconds, the desk warns: timers still follow the host, but times of day may not agree, so set both computers to set their time automatically.
- **Notices** (the bell on the main desk; Notices on a joined desk): a short private message to everyone, the main desk, a role, or **one person** (Send to → One person: a paired desk or phone by name), optionally urgent, tied to the event happening now. Answer **Seen**, **Ready** or **Unable**; the sender and everyone else who receives it see the answer. Each joined desk and phone receives only the notices for it (everyone's, its role's, its own name's and the ones it sent); the main desk sees them all. Nothing here reaches a screen or the service log.
- **Action requests** (a notice that asks for something): under the message choose **Ask to show a verse** (type the reference), **Ask to take a scene** or **Ask to start an item**. The recipient gets one button for it ("Show Romans 8:28", "Take Camera + lyrics", "Start Sermon"); nothing happens until they press it. It answers **Ready** only when it was done; if the main desk refused it (the desk's role does not allow it, control was taken back, or the main desk moved to another service), it answers **Unable** and the desk shows why. It runs with the recipient's own permissions: a Timekeeper's desk can start an item, not show a verse. A scene request switches the outputs already showing a scene (else the main output).
- **Talk** (Push-to-Talk with the crew, full duplex): a joined desk presses **Join the talk channel** (Production → Operators; the computer asks once for the microphone), then holds **Hold to talk** (mouse, finger, or Space / Enter on the button). Everyone can talk at once; nobody is cut off. Who is talking shows on every desk (a green mark is someone actually heard). On the main desk the microphone button appears in the top bar once someone has joined, with the crew's volume beside it. Letting go, leaving the window or losing the network stops talking. Crew voices play only on that computer's own output: never on a screen, the PA, OBS, NDI, a recording or listening. A paired **phone** can talk too, from the phone remote page (**Join the talk channel**, then hold **Hold to talk**), but only where its browser allows the microphone: on a secure (https) page. To make that page secure on the church Wi-Fi, tick **Secure page for phones (https)** in Settings → Remote before starting the HTTP listener: the phone page is then also served over https on the next port (8081 beside 8080), and the pairing code opens it. Each phone either accepts its browser's warning once ("not private" / "not trusted": this computer made its own certificate), or, to trust it properly, opens `http://<this computer>:8080/rhema-ca.pem` and installs the certificate (iPhone: Settings → General → VPN & Device Management, then About → Certificate Trust Settings; Android: Settings → Security → Install a certificate). Without it, a phone shows "Talking from this phone needs a secure page"; notices and the other buttons work as usual.
- **Talk channels and private calls:** everyone is always in **All crew**; each joined desk also hears **Production** and **Stage & worship** unless it unticks them (Hear). **Talk to** picks where your voice goes: All crew, a channel, or **Only…** one person (a private call; the main desk too). The main desk hears every channel and has its own Talk to beside its microphone button, with one more choice: **All crew, priority**, for when it must be heard now: everyone else is turned down while the main desk holds Talk, and comes back when it lets go. The crew list shows where each person is talking ("→ Production").
- **If Talk drops:** when the main desk drops off the network, a joined desk stops sending your voice at once and shows **Talk dropped — reconnecting…**. It tries to join again by itself for about a minute and a half and says **Back in the talk channel** when it is in again. Your microphone stays off until you press Talk again. If the main desk cannot be reached by then, press **Join the talk channel** once it is back. A desk or phone that drops off leaves the main desk's crew list within a few seconds. On a phone, a dropped Talk says so; press **Join the talk channel** again.
- **Your headset:** Settings → Audio → **Talk headset** (or **Headset** under Talk on a joined desk) picks, for this computer only, the microphone you talk with and where you hear the crew. It is separate from the listening microphone. **System microphone** and **System output** follow the computer's own sound settings. If the chosen headset is unplugged, Rhema uses the computer's own microphone and says so. Where the computer cannot pick an output (the Mac app does not allow it), Rhema says the crew plays on the system output: choose the headset in the computer's sound settings. Device names show after the microphone has been allowed once.
- **Take back control:** on the host, Production → Operators (or Settings → Remote) has **Take back control** beside each paired desk or phone. Its commands stop at once, it stays paired with its role, and it shows *Paused by the main desk*; it still sees the service and keeps Talk and notices. **Give control back** ends it. Both are written in the service log, and the pause stays if Rhema restarts.
- **One service at a time:** each joined desk tells the host which service it is looking at with every command. If the host has moved to another service (say from the 9 AM to the 11 AM) and the desk has not caught up yet, the host refuses the command, and the desk says so and refreshes; press again once it shows the right service. The phone remote page and scripts that do not say which service they mean work as before.
- If the network drops, the joined computer says *Reconnecting…* and catches up by itself; the host carries on. **Leave** stops following; **Forget this host** also drops its key (revoke the device on the host to be sure).

## When something fails

The main computer never depends on anyone else: everything on the screens can be done from it alone, whatever happens to the network, the joined desks or the talk channel.

| What fails | What keeps working | What you see | What to do |
|---|---|---|---|
| The network, or the HTTP listener stops | Every screen, output and timer on the main computer | Joined desks say **Reconnecting…** and their buttons stop; phones say no answer | Nothing on the main desk. Joined desks come back by themselves and catch up (notices included: the main desk keeps the last 100 for the service) |
| A joined computer or phone dies | Everything; nothing it did is undone | It disappears from the talk channel and its notices stop | Carry on from the main desk; Settings → Remote → revoke it if it is lost (it also leaves the talk channel at once) |
| The talk channel drops | Screens, outputs, notices | Each desk's microphone stops; it shows "Talk dropped — reconnecting…" and joins again by itself, or asks you to join again | Use **notices** and the **stage message** meanwhile; press Talk again once it says "Back in the talk channel" |
| A TV or OBS browser page sticks | Every other output | Production → Screens: **behind: not showing the latest** in red | Reload that page; if the link was shared, **New link** in the output's settings |
| A phone camera stops (battery, Wi-Fi, locked) | Every screen; the scene shows the camera's fallback words (or its background) in its box | Production → Show health: **Needs attention** "Pulpit camera is not sending…"; Home warns | Check the phone: charging, on the church Wi-Fi, camera page open, **Start camera**; or Take a scene without that camera |
| A Google TV goes blank or shows its code | Every other output | Show health: the feed's screen count drops, or **Check TV** says what the TV shows | Press OK on the TV's remote, then **Show on a Google TV** again with the new code |
| An NDI sender fails | Every other output | Production → Screens: **Needs attention** names it | Outputs → turn it off and on; check OBS |
| A projector is unplugged, or the display sleeps | Every other output | The output is reported off (macOS lists no monitor while the display sleeps) | Plug it back or wake the display; turn the output on again |
| Rhema itself closes unexpectedly | Nothing until it starts again | On the next start: **Rhema closed unexpectedly…** | **Put back on the screens** (or **Not now**); check the screens, then carry on. The service log and the last 100 notices (with their answers) are back by themselves; joined desks see them again when they reconnect |

Black and Logo always work from the main desk and cover every screen and feed, whatever else is happening. The service log keeps what happened, with who did it.

## Timing and the stage

The service timer (Present header) also shows, once items have planned minutes and the timer runs, the planned end time and, when the service is a minute or more off plan, when it now looks like ending ("Planned end 12:30 · now about 12:41"). If the timer was started late, "Correct the timer" moves it by a minute either way; each correction is a line in the service log.

An item's planned **Time** (Prepare) takes minutes (`35`), minutes and seconds (`4:30`), hours (`1:10:00`, `1h10`); it is applied when you press Enter or leave the field, and anything else is marked and not applied. An item can also have an **end by** time (Prepare, beside its planned time: "sermon ends by 12:15"). While it is the item in hand, the timer chip shows "by 12:15 · 6 min", amber in the last two minutes and red once the time has passed.


- **Time warnings on the stage** (Design → Stage → Time warnings): "5 minutes left" (choose 1 to 30) and "Time is up" appear as a stage message as the running timer reaches them, once each; only the stage sees them, a message you sent is never covered, and rehearsal never sends them. Off until you tick them.
- **Timer**: monotonic (ignores clock changes); amber under two minutes, red when over. Planned minutes per item give "n min late/early".
- **The event clock** (Production → Timekeeper): which event of the run of show is happening, kept apart from the screens. **Follows the screens** (default): an item's event starts when its content goes on air. **I start each event**: only Start / Back one move it, so a timekeeper can run the times while others show verses and songs out of order. Timing, the stage finish line and each item's message and cue follow it; the service log records each event start.
- **Skipped items:** an item of the run of show that never went on air while a later one did is **Skipped** (Prepare → Run of show and its table, Production → Timekeeper). It takes no time in what is expected: the expected times carry on from the item on now, and the plan keeps its planned minutes.
- **Hold** (the service timer, Production → Timekeeper, or a joined Timekeeper desk): "Waiting for the pastor" goes in the service log and on the stage display; loops and timed moves wait until **Resume**. A hold from a joined desk says which desk.
- **Countdown to the next item or a milestone:** a clock that counts down to when the next item is now expected to start, or to a milestone (the end of the main service, or an item's end by). It moves as the service runs late or early, skips skipped items, and counts across midnight. Put one in a scene (Production → Programs → a Clock layer → Shows: **Time until the next item** or **Time until a milestone**), on the stage display (Design → Stage → **Countdown**), or watch it in Production → Timekeeper (**Count down to**). On the congregation screens it stops at 0:00 and shows nothing once there is no next item; the stage and Timekeeper say how far over it is ("Next: Sermon 0:45 over"). The main service needs a start time (Prepare).
- **Chime** (Production → Timekeeper → Countdown): a short tone on this computer only, at the minutes you choose before what Timekeeper counts down to and again at zero ("At zero only" for just one). Off until you tick it; the screens, the stage and the online feed never hear it.
- **Run of show on every desk:** a computer joined to the host (any role) shows the host's run of show, read only: each item's planned and expected times, how far off plan, its end by, and Done / On now / Skipped / Cut short. Nothing on it can be pressed; a Timekeeper desk still runs the clock from its own controls above it. If the host sends no times (no start time yet, or a host not yet updated) it says so.
- **Running late or early:** **−5 min / +5 min** (Production → Timekeeper, Prepare → Run of show, or a joined Timekeeper desk) move the service's one shared offset: every expected time, the stage finish line and every desk follow it; the plan and the screens do not change. **On schedule** sets it back. The service log records each change and who made it; another service starts at zero.
- **Message stage**: a framed banner on stage outputs only. Clear it from the same control.
- **Rehearsal**: freezes every output at what it shows. Turning it off puts back the program, lower third, ticker, stage message, service timer and each screen's scene as they were (nothing rehearsed is shown or logged); a scene taken in rehearsal (Programs, the Present Scenes strip or a joined Screens desk) never reaches a screen. **Show this live** leaves rehearsal and puts the rehearsed words on air (the approval question applies), everything else, scenes included, still coming back. A loop or timed move running on air waits through rehearsal and carries on after.
- **Design → Library**: ready-made looks (Bible and songs full screen, keyed lower thirds, speaker names, ticker, stage, camera scenes) in six families, with filters and favourites. **Use** adds your own copy to your looks; nothing on the screens changes until you choose it for an output in its settings. **Use and edit** opens the copy; a theme copy can be reset to the library look (not while a screen shows it). **Use with church colours** adds the copy in your Brand Kit colours and fonts (set them in Design → Brand Kit first); if a colour would be hard to read on that look, the copy keeps the look's own and says so. Filter by language: Yorùbá, English, or Both together (looks that show two languages at once). See `docs/rhema-studio/look-library.md`.
- **Design → Themes → Live edit**: off by default, so editing a theme the screens use changes nothing on air until you save. On, the screens using that theme follow your edits (the header says how many); it turns off when you leave the theme.

## Data safety

- Every save of a service is a version (Prepare → History): compare and restore; a restore is itself a new version. **Approve** (Prepare, next to Save) pins the saved version as the one for the day: History marks it, it is never pruned, and Home warns when the service has changed since.
- Archive: **Save this service as a file** carries one service with its songs and pictures to another computer (checksummed; a damaged file is refused), and **Back up now / Restore** for the whole database. A restore refuses files that are not a Rhema Studio database and keeps the previous database as a snapshot next to it. Library: export/import songs (Rhema JSON, OpenLyrics).
- Before any upgrade the app copies the database to `studio.db.before-<migration>.bak`.

## Church folder (prepare at home, present at church)

Archive → Church folder → Choose folder…: a NAS share, or a folder kept in step by Google Drive, OneDrive, Dropbox or Syncthing, chosen on every computer. In Prepare, **Publish** puts the saved service there as a new file named with its date, version and a short checksum (`Sunday 2026-10-25 v7 3f9a0c21b7d4.rhema-service.json`); older versions stay. Approving and publishing again makes a new file that says so. On Home, **Church folder** lists the newest version of each service (approved at home or not, opened here or not); **Open** adds it on this computer with its songs and pictures. Approve it again here before Sunday. If someone publishes a newer version later, Prepare says "A newer version (v8) is in the church folder" above the service you opened, and Home marks the row "newer than the copy opened here"; **Open the newer one** adds it as its own service and keeps yours. Nothing is replaced by itself. A file still syncing shows as "damaged … may still be syncing" and cannot be opened until it is complete.

## Keeping what was said (optional)

When speech recognition ran during the service, Archive → Service log offers "Include what was said". Ticked, the recognised passages (with times) are added to the log you keep or save; Earlier logs can then find a service by a phrase from the sermon. It is machine output, not checked; keep it only if the speakers know it is recorded. Off by default, every time.

## Song usage (licence reports)

Archive → Song usage: choose a date range (default: the last six months), Show, then Save as CSV… The report counts saved services dated in the range (a song sung twice in one service counts once), with each song's CCLI number, licence and last use, ready to copy into a CCLI (or other licensing body) report. Services without a date are not counted, so give each service its date.

## Speech recognition and Auto

While Rhema listens, verses it hears in the sermon appear in the preview and the detections list; the operator presents them. With a service open, a heard verse that is already in the service makes that item flash; it does not move Next and is not added to the service (add it from the detections list if you want it kept). Without a service open, heard verses collect in the list as before. **Auto** (on the Live panel in Present → Advanced view: Off, Bible feeds only or On, or Settings → Heard verses) makes heard verses replace what is on screen without Take live. It starts off, also after updating from a build where it was on by default: turn it on again if your church relies on it; while it is on and Rhema is listening, Present shows "Auto-live on" in the header, and clicking it turns Auto off. A third choice, **Bible feeds only**, sends a confident heard verse to the feeds that follow Bible (an OBS lower third, a browser feed, a scene's Bible box) by itself, even while the projector is off air, and never changes the main screens; Present → Live → Sources then shows "Auto: Bible feeds" (click it to turn Auto off) and each verse it sent reads "by Auto". A build from before this choice reads it as Auto off.

## Translations

Quick find takes a full reference, a book or chapter alone ("1 Samuel", "1 Kings 3", "Psalm 23": that chapter's first verse comes first, above any word matches), and ordinals in words ("First Samuel 3:10", and the Yorùbá order "Samuẹli Kínní 3:10", "Ọba Kejì 2:9").

Quick find understands the Yorùbá Bible's own book names as well as the English ones, with or without accents: "Johanu 3:16", "Jòhánù 3 16", "1 Ọba 3:9", "Ìṣe àwọn Aposteli 2:38" (or just "Ise 2:38"). The names are the ones printed in the bundled Yorùbá edition; other Yorùbá Bibles may spell some books differently (for example "Johannu").

- A saved item goes live in the translation it was saved with; spontaneous verses follow your active translations. The Present header chip switches to "Override" to show everything in the current translation. A missing translation is reported, never substituted.

## Hymn book (CAC Gospel Hymn Book)

Prepare → **Hymn book** lists the Christ Apostolic Church Gospel Hymn Book in English and Yorùbá, apart from the Songs library: **Part 1** (1–1000) and **Part 2 · Various** (V1–V50). Find a hymn by number (`245`; `V12` or `v012` for Part 2) or by words in either language; click to preview; **Add** puts it in the service. "First: Yorùbá / English" is remembered and sets the order of new items; each item's EN · YO chips still change it in the rundown.

- **Import:** the first time, **Import the hymn book…** and choose `hymns_combined.json`. The hymns are kept in this computer's database only; they are not part of the app or its repository. **Import the file again…** updates them in place (by number), so services that use them keep working; a number already used by one of your own songs in a "CAC" hymnbook is left alone and reported.
- **On screen** a hymn is a bilingual song: each verse with its chorus, both languages styled by the theme's first/second language settings, the footer "<title> · CAC Gospel Hymn Book 245". An output set to one language shows only that one. Quick find also finds `CAC 245`.
- Hymns never appear in the Songs tab, its count or its export.

## Your desk (the foot of the sidebar)

The bottom of the sidebar shows who is at this computer: your initials, your name (or **Add your name**) and what this computer is to the team: **Main desk**, or, while it has joined another Rhema, the role the host gave it ("Bible desk · joined …"). Click it (or Tab to it and press Enter) for the Desk menu:

- **Your name:** type it and press Enter (or click away). Escape puts back what was there. It is the same name as Team → Your name.
- **Appearance:** Light, Dark or System (follows the computer). The whole studio changes at once; Present's live console stays dark.
- **Settings** (also ⌘, / Ctrl+,), **Complete setup** (the setup steps for this church), **Keyboard shortcuts**, **Help and the tour**, **Diagnostics**, and **About Rhema Studio** with the version.

With a narrow window the sidebar shows only icons; the desk is then your initials, with the same menu.

## Finding a setting

Settings has a **Search settings** box at the top of its list. Type a word you see on the setting or one you would use for it ("gain", "microphone", "deepgram", "pair", "yoruba"): only the sections that hold it stay in the list, each naming the matching settings, and the matches are highlighted when you open one. Enter opens the first; Esc empties the box. Light and dark are not in Settings: they are under Appearance in the Desk menu.

## Speech recognition and the Deepgram key

Settings → Speech Recognition is the one place for the cloud speech key: choose **Cloud (Deepgram)**, type or paste the key and **Save**. The eye button shows or hides it, **Clear** removes it, and typing a new one and saving replaces it. It is kept in the system keychain where the computer has one. There is no separate Cloud keys page any more; an old link to it opens Speech Recognition.

## Who did what

Team → Your name (or your name in the Desk menu) is optional and local. When set it is written on every change (saves, approvals, imports) in the content database's audit table and at the top of the saved service log. Home's **Team changes** shows the latest of these for the open service (or today's): comments from others (new ones marked), who saved it last and who approved it; click one to open Prepare on that item or on the service's History.

## Diagnostics

Settings → Diagnostics → Save logs. Each output also logs how long screens take to appear: a "[latency]" summary every 20 changes (median and slowest, from send to drawn) and a warning for any change over 100 ms, so a slow computer shows up in the saved logs. The content database path (and the copy from before the last upgrade) is shown in Archive → Backups.
