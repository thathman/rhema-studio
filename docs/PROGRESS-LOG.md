## 2026-10-23 — Rhema finds Google TVs by itself (#198)

- **Branch / PR:** `op-008/tv-discovery` (#318, on top of #319 `sh-004/health-cameras-tvs`).
- **Security (review of #318):** a device can advertise `_rhema-tv._tcp` and pretend to be a TV, so the link now goes only to a TV that proves it shows the typed code. A plain HMAC of the code from the TV was not enough: one answer lets anyone try all million six-digit codes offline in under a second (so a pretend TV, or anyone, could learn the code from the real TV), and counting tries cannot stop that. Instead `POST /challenge {x}` → `{y, proof}` is SPAKE2 in the RFC 3526 2048-bit group (`CodeProof.java` / `commands/tv_proof.rs`, w = SHA-256("rhema-tv code:" + code) mod q, M/N = squared long hashes of "rhema-tv M"/"rhema-tv N"); key = SHA-256("rhema-tv-1" ‖ X ‖ Y ‖ K ‖ w ‖ "ip:port" as Rhema reached the TV), TV proof = HMAC-SHA256(key, "tv") checked by Rhema in constant time (`verify_slice`), then `POST /show {url, proof = HMAC(key, "desk" + url)}` from the same computer within 30 s, one use. Someone without the code can test one guess per exchange, so the TV counts each exchange as a try (five, then OK for a new code); the address in the key stops a pretend TV from passing Rhema's messages on to the real one. `tv_show` resolves the address to IPv4 first, never uses a proxy, refuses a receiver without `/challenge` (404: "Update Rhema Receiver on the TV (1.2 or later)") and never sends the link when the proof fails. Receiver 1.2.0.0 (versionCode 3) no longer takes the code in `/show`. Discovery keeps only private (RFC 1918) or link-local IPv4 on port 8095, the list shows each address, and nothing is filled in by itself.
- **Behaviour:** Rhema Receiver (android-tv, now versionCode 3 / 1.2.0.0 with #319's GET /status kept) registers `_rhema-tv._tcp` on port 8095 with Android NSD under the TV's device name (`MainActivity.advertise`, anonymous listener; a failed registration retries after 10 s; unregistered in `onDestroy`), and its info screen shows the TV name. Only INTERNET is needed (NSD is done by the system's mDNS service; no multicast lock or network-state permission). Rust: `tv_discover` in `commands/join.rs` browses `_rhema-tv._tcp.local.` with `mdns-sd` 0.21 (MIT/Apache-2.0, default features off, app crate only) for 2.5 s on a blocking thread and returns `[{name, address: "ip:port"}]`: sorted by name, one entry per address, removed services dropped. UI: `ShowOnTv` looks once on mount, lists TVs (name and address) as toggle buttons that fill the address and focus the code, **Find TVs** looks again, "No TV found" falls back to typing. `Info.plist` gets `NSLocalNetworkUsageDescription` (the text of macOS's local-network prompt).
