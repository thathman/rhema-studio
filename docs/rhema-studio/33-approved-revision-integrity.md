# Approved design revision integrity (#398)

Local implementation, 27 October 2026; no production or hardware acceptance claim.
Authority: latest owner-ratified #243/#246 and docs 28–32. This extends #414's existing per-output scene snapshots; queue insertion and scene layout pinning remain in place.

Approval captures referenced reusable scenes, their output-specific looks, Brand Kit logo and media IDs in the local content database, alongside the existing service-row and song pins. Refresh approval is explicit and does not Take anything. Refreshing any already-approved release, including a legacy approval without a design manifest, creates a new service revision and retains the previous record in History's normal revision window. Repeating an identical approval request is idempotent. Files referenced by retained manifests cannot be deleted.

An item's explicitly armed scene Take resolves the approved scene and its captured appearance for each target congregation output. An output added after approval requires approval refresh before it can use that approved scene; current mutable looks are never substituted as an approved appearance. A normal manual scene Take captures its saved scene, looks and logo. Subsequent reusable scene/look/logo edits leave those snapshots unchanged. Live source activations still update layers intentionally following those sources.

In Present, **Refresh saved preview** selects the current saved scene for the chosen output's preview. It does not update output state or call Take. The separate **Take scene** action applies the saved scene/look/logo to that output. The matching-revision case remains a disabled no-op. Rehearsal restores both the original layout and appearance; public outputs retain their pre-rehearsal scene. Explicit armed Live Design and existing explicit scene deletion/release semantics are preserved.

Compatibility is additive: migration 0014 adds manifest/media-reference tables and runs through the existing backup-before-upgrade path. Legacy services and outputs without manifests remain loadable/saveable; their historical designs cannot be reconstructed. Refresh approval or deliberately Take the saved scene to establish pins. The approval control describes missing legacy metadata. Legacy approval callers cannot erase an existing design-aware release; re-approving that exact release without a new manifest is a no-op. An older binary refuses a newer database through the existing version guard; do not downgrade a migrated database. Use its pre-migration backup with the older binary if needed.

Scope limits: these local design manifests are not added to portable service packages/church-folder import; imported services still require approval on the receiving computer. This is not a new Avnac document model, a hardware ACK mechanism, or a redesign of source activation. Existing shared-host scene command authorization/version checks remain in place. Real OBS/NDI/TV/camera rendering, WAN-unplugged cold boot and full native desktop rehearsal require separate validation.
