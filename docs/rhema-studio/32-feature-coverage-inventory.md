## B. Priority facts Codex must explicitly verify before declaring "all changes done"

1. **Architecture and UX**: Working versions of six primary routes, one Live with no duplicate Standard/Advanced queue, one Design gallery/editor and contextual picker, correct Add Event placement/group drag/drop and consistent service/phase behavior.
2. **State and output safety**: Live Bible source one activation → each audience's own chosen layout and language; Save Draft does not alter current outputs; rehearsal does not leak; group/all Take only when clearly authorized, with safe affected-output summary.
3. **Content integrity**: Every existing Bible, Song, Hymn, Slide/Media, Cue, Theme and Event imported into new model without lost IDs, unsupported unknown data or language/copyright metadata. Empty/failed searches surfaced honestly.
4. **User experience**: Theme "Use"/"Use and edit" ambiguity gone; long galleries filterable; lower-third/ticker/Stage/countdown creators arise from actual task context; Add palette closes and focuses new item; readable buttons and keyboard/D-pad accessibility.
5. **Comms**: Acknowledged Notices and Action Requests work privately from multiple operator clients; *simultaneous* PTT does not accidentally use exclusive floor control; both talkers appear in Who's Talking; optional phone input.
6. **AI and collaboration**: MCP generates a real editable service draft and native visual drafts, with provenance/permissions; shared planning from home does not mutate an active church show until approved and synced.
7. **Engage**: Internet phone quiz with 15–600-second lobby, scoreboard/fastest-response behavior, never required for core Live; include true deployment/device status.
8. **Three devices**: Real standalone TV/Cam/Companion upgrade UI and behavior, shared pairing, independent online/sanctuary programs, actual measured FPS/latency, LAN/WAN-off recovery.
9. **Documentation**: Final wiki/manual and operator quick guides cover all tasks with real screenshots. A screenshot or an open PR is not acceptance evidence.

## C. Coverage audit / status protocol

This checklist records **owner-approved intent** but not feature readiness. For every row, maintain:

`Area | Owner issue | As built in main | In PR | Still missing | Tested on device | Owner accepted`.

Evidence should include file/commit link, test IDs, runtime screenshots and physical output when needed. Where a proposed component is not approved, keep it separate from approved features. **New work is NOT authorized to delete earlier architecture just because it is not repeated in a shorter handover.**
