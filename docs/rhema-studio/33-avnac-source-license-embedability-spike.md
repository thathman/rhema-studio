# Avnac source, license and embedability spike

**Date:** 2026-10-27 · **Scope:** Issues [#443](https://github.com/thathman/rhema-studio/issues/443) and [#448](https://github.com/thathman/rhema-studio/issues/448). Source inspection only; no Avnac code/assets imported, no dependency or Rhema license change, and no renderer replacement.

## Source, license and provenance

The `studio` branch resolved to **`79a4bed4a468d59e21339ad9a62a476aa6264b6f`**; a later `ls-remote` check returned the same branch tip. See the [pinned commit](https://github.com/striker561/Avnac-Studio/commit/79a4bed4a468d59e21339ad9a62a476aa6264b6f).

At that commit, the repository has a root [GNU GPL version 3 license](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/LICENSE). Its [README](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/README.md) describes Avnac Studio as a Wails/Go desktop port of [Avnac](https://github.com/akinloluwami/avnac), credits desktop maintainers `striker561` and `d3uceY`, credits `akinloluwami` for the original web app, and says desktop-specific work is on `studio` while `main` mirrors the original app. The README states “GPL © 2026 striker561, d3uceY.” The inspected tree exposed only the root license file; no separate `NOTICE`, `COPYRIGHT`, or file-level provenance map was found. This does not establish provenance for every file, font, or bundled asset.

The pinned [frontend lockfile](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/package-lock.json) records MIT license identifiers for editor-related direct packages: React/React DOM 19.2.5, Zustand 5.0.12, TanStack React Router 1.168.25, Hugeicons React 1.1.6 and core-free icons 1.2.1, `qrcode` 1.5.4, and `@tambo-ai/react` 1.2.6. A static import scan found no third-party npm imports in the Saraswati core or Canvas2D renderer paths; they use TypeScript/browser canvas APIs. These lockfile identifiers are not a transitive dependency, asset, font, or legal audit.

The [#443 owner clarification](https://github.com/thathman/rhema-studio/issues/443#issuecomment-6413841462) says internal church use is intended and no app distribution is planned, while also stating that this grants no new license rights and that public-repository source commits are a separate compliance concern. **Any GPL combination/import and resulting distribution must receive owner/legal review before source import; this spike makes no legal conclusion.**

## Entry points and Rhema seam

- **Document/scene model:** [`frontend/src/lib/saraswati/index.ts`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/saraswati/index.ts), [command reducer](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/saraswati/commands/reducer.ts), and [render commands](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/saraswati/render/commands.ts). Document adapters are [`avnac-document.ts`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/avnac-document.ts) and [`avnac-multi-page-document.ts`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/avnac-multi-page-document.ts).
- **Renderer:** [`frontend/src/lib/renderer/index.ts`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/renderer/index.ts) exports the [Canvas2D renderer](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/lib/renderer/backends/canvas2d/renderer.ts). A Pixi-named backend file exists but is not exported there and `pixi.js` is not a declared frontend dependency.
- **Editor:** [`scene-editor-page.tsx`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/features/scene-editor/scene-editor-page.tsx), [`scene-editor-canvas.tsx`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/features/scene-editor/scene-editor-canvas.tsx), and its [Zustand store](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/features/scene-editor/store/scene-editor-store.ts). MCP UI transport is in [`use-mcp-actions.ts`](https://github.com/striker561/Avnac-Studio/blob/79a4bed4a468d59e21339ad9a62a476aa6264b6f/frontend/src/features/scene-editor/use-mcp-actions.ts) and `frontend/src/lib/mcp/`.

Rhema already hosts a React/Vite frontend in its Tauri shell. That is a plausible seam for a contextual editor component plus a versioned document adapter. Rhema currently has a Fabric-based theme `DesignCanvas`, a service-bound text/announcement/QR `SlideComposer`, and its own scene renderer for live camera/video and output layers. A future adapter could store Avnac-style editable documents in Rhema’s canonical design records, resolve typed Rhema source bindings there, and keep the existing output renderer responsible for live scenes.

The upstream editor is **not a drop-in page**: it uses TanStack routing, its own components and IndexedDB document store, and generated Wails calls (`ConfirmDialog` in the editor store; `SubmitResponse` in MCP actions). Those need Rhema/Tauri adapters. Its versioned document shape and migration adapters also differ from Rhema’s theme, slide, source, and output models. Camera transport, output-specific language policy, Take authorization, and draft/live revision boundaries remain Rhema responsibilities; parity and migration are unproven.

## Bounded next step

First obtain owner/legal review of the GPL/provenance and intended public-repository obligations. If cleared, run a separate, isolated compatibility prototype with an explicitly selected source subset and preserved notices: adapt a versioned document, edit/render text plus an image, save/reopen offline, and exercise a 100-layer scene on macOS and Windows while confirming Rhema’s current renderer remains unchanged, matching #443’s spike gate. Do not import source before that gate; defer dynamic live nodes and output integration to later reviewed work. This spike did not run application tests or performance checks.
